# Auth dan Management API — baseline v1

> **Status:** FINAL — Perencanaan MVP v1.0 (19 Oktober 2026). Final sebagai acuan implementasi; bukan klaim implementasi selesai atau siap produksi.
> Diputuskan 19 Oktober 2026 melalui delegasi pengguna. Kontrak perencanaan; OpenAPI dan implementasi belum dibuat.
> Kebijakan auth/TTL: [Technical Decisions](./gps-tracking-technical-decisions.md). Kontrak tracking: [API Contract](./gps-tracking-api-contract.md).

## 1. Konvensi

Semua path relatif `/v1`, JSON strict (unknown fields ditolak), UTC/RFC3339, UUID. Error memakai envelope API Contract. Mutasi cookie membutuhkan Origin dan CSRF, kecuali token-link redemption yang memakai pre-auth CSRF. Tenant-scoped request membutuhkan `X-Organization-Id`; body tidak boleh menetapkan tenant. Error `401` untuk unauthenticated, `403` insufficient role/scope/CSRF/MFA, `404` objek tenant lain atau hilang, `409` invariant conflict, `422` validation, `429` rate limited. Respons auth/secret memakai `Cache-Control: no-store`.

Daftar memakai `{data:[],next_cursor:null}`, limit default 50/max 100, sort `created_at DESC,id DESC`, cursor ditandatangani dan mengikat tenant/filter. PATCH tidak menghapus field yang omitted; null hanya sah pada field nullable. Response resource selalu memuat ID dan timestamps; tenant resource memuat `tenant_id`. Audit/error tidak memuat secret atau raw coordinate.

## 2. Auth dan sesi

| Method/path                            | Body/input                     | Sukses dan perilaku                                                                                                                                                               |
| -------------------------------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET `/auth/csrf`                       | —                              | 200 `{csrf_token}`; pre-auth/sesi, same-origin, no-store                                                                                                                          |
| POST `/auth/login`                     | `{email,password}`             | 200 `{state:"authenticated",user}` + cookie jika MFA tidak diaktifkan/diperlukan; atau `{state:"mfa_required"}` / `{state:"mfa_enrollment_required"}` + challenge cookie terbatas |
| POST `/auth/mfa/verify`                | `{code}`                       | Challenge cookie, 200 `{state:"authenticated",user}`, rotate cookie; konsumsi TOTP step atomik                                                                                    |
| POST `/auth/mfa/enrollment`            | `{}`                           | Restricted enrollment atau sesi + recent auth, 200 `{secret,otpauth_uri}` sekali; pending 10 menit; tidak mengganti faktor aktif                                                  |
| POST `/auth/mfa/enrollment/confirm`    | `{code}`                       | 200 `{recovery_codes:[...]}`, aktifkan secret, issue session atau revoke dan login ulang jika recovery                                                                            |
| POST `/auth/mfa/recover`               | `{recovery_code}`              | Challenge hasil password, 200 `{state:"mfa_enrollment_required"}`; konsumsi code, cabut sesi lama, akses hanya enroll/logout                                                      |
| POST `/auth/reauthenticate`            | `{password,code?}`             | Sesi, 204; code wajib jika MFA enrolled/required; berlaku 5 menit                                                                                                                 |
| POST `/auth/mfa/recovery-codes/rotate` | `{}`                           | Sesi + recent auth, 200 `{recovery_codes:[...]}`; invalidasi kode lama                                                                                                            |
| DELETE `/auth/mfa`                     | —                              | Sesi + recent auth, 204 hanya jika MFA tidak required; cabut sesi dan login ulang                                                                                                 |
| POST `/auth/logout`                    | `{}`                           | 204, cabut cookie/session; idempotent                                                                                                                                             |
| GET `/auth/me`                         | —                              | 200 `{user,mfa_required,mfa_enabled,memberships:[...]}`; tidak mengungkap secret/hash                                                                                             |
| GET `/auth/sessions`                   | —                              | 200 daftar `{id,created_at,last_used_at,expires_at,current,device_label}`; label user agent disanitasi                                                                            |
| DELETE `/auth/sessions/{id}`           | —                              | 204; hanya milik sendiri; WS terkait ditutup                                                                                                                                      |
| POST `/auth/activate`                  | `{token,new_password}`         | 204; aktivasi akun pending sekali pakai, password ditetapkan pemilik email, tidak auto-login                                                                                      |
| POST `/auth/password/forgot`           | `{email}`                      | 202 `{message:"If eligible, instructions will be sent"}` untuk semua email; rate limit                                                                                            |
| POST `/auth/password/reset`            | `{token,new_password}`         | 204; konsumsi reset token, cabut semua sesi; MFA tidak dihapus, tidak auto-login                                                                                                  |
| PUT `/auth/password`                   | `{new_password}`               | Sesi + recent auth, 204; cabut sesi, login ulang                                                                                                                                  |
| POST `/auth/recovery/complete`         | `{token,email_token,password}` | Otorisasi recovery CLI + bukti email, 200 restricted enrollment; tidak menghasilkan sesi penuh                                                                                    |

User: `{id,email,display_name,status,created_at,updated_at}`. Secret password/TOTP dan recovery code tidak masuk user schema. Tidak ada refresh JWT endpoint: browser memakai opaque server session dengan idle/absolute expiry. Challenge cookie memakai properti keamanan cookie sesi tetapi nama terpisah dan TTL 5 menit. Maksimal lima percobaan challenge; invalidasi setelah habis. Enrollment endpoint pada full session memerlukan reauth; pada restricted session harus memverifikasi password-stage challenge yang sah.

CLI bootstrap/recovery harus mengikat email/account, reason dan case ID; gunakan input secret tersembunyi, bukan command-line arg/log. Recovery kehilangan semua faktor memerlukan operator server dan verifikasi identitas tercatat; tidak ada endpoint publik untuk menciptakan authorization recovery.

## 3. Organisasi, membership, undangan dan grant

| Method/path                                  | Izin                                                                      | Body dan hasil                                                                                                                                                        |
| -------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET `/organizations`                         | User login                                                                | 200 daftar organisasi membership user; platform admin tidak mendapat data lokasi                                                                                      |
| POST `/platform/organizations`               | Platform admin + recent MFA                                               | `{name,admin_email}`; 201 `{organization,invitation_id}`; org dan invite dibuat atomik, email via outbox                                                              |
| GET `/platform/organizations`                | Platform admin                                                            | 200 daftar metadata organisasi, tanpa coordinates                                                                                                                     |
| PATCH `/platform/organizations/{id}`         | Platform admin + recent MFA                                               | `{status:"active"                                                                                                                                                     | "suspended"}`; 200 organization; invalidasi tenant sessions/subscriptions |
| GET `/organization`                          | Membership aktif                                                          | 200 organisasi aktif dari header                                                                                                                                      |
| PATCH `/organization`                        | Org admin + recent auth                                                   | `{name}`; 200 organization                                                                                                                                            |
| GET `/organization/members`                  | Org admin                                                                 | 200 daftar membership + user display fields                                                                                                                           |
| POST `/organization/invitations`             | Org admin + recent auth                                                   | `{email,role}`; 201 invitation; duplicate pending invite -> 409, resend lewat endpoint berikut                                                                        |
| GET `/organization/invitations`              | Org admin                                                                 | 200 daftar metadata invite, tanpa token                                                                                                                               |
| POST `/organization/invitations/{id}/resend` | Org admin + recent auth                                                   | `{}`; 202; token lama revoked, TTL dimulai ulang, rate limited                                                                                                        |
| DELETE `/organization/invitations/{id}`      | Org admin + recent auth                                                   | 204, revoked                                                                                                                                                          |
| POST `/auth/invitations/accept`              | Token + pre-auth CSRF                                                     | `{token,password?,display_name?}`; 200 `{state:"login_required"}` untuk akun baru atau `{state:"accepted"}` untuk matching signed-in user; tidak auto-login akun baru |
| PATCH `/organization/members/{user_id}`      | Org admin + recent auth                                                   | `{role?,status?}`; 200 membership; status active/suspended, role admin/operator/viewer, proteksi admin terakhir                                                       |
| DELETE `/organization/members/{user_id}`     | Org admin + recent auth                                                   | 204 revoke membership/grants/subscriptions; proteksi admin terakhir                                                                                                   |
| GET `/organization/members/{user_id}/grants` | Active member may read own grants; org admin may read any member's grants | 200 grant list; cross-tenant and non-admin reads of another member denied                                                                                             |
| PUT `/organization/members/{user_id}/grants` | Org admin + recent auth                                                   | `{grants:[...]}`; 200 grant list; replace atomik, maksimal 1000 entries, semua referensi diverifikasi tenant                                                          |

Organization `{id,name,status,created_at,updated_at}`. Membership `{id,tenant_id,user_id,role,status,created_at,updated_at}`. Invitation `{id,tenant_id,email,role,status,expires_at,created_at}`. Grant `{resource_type:"organization"|"target"|"device",resource_id,permissions:[...]}`. Organization resource hanya izin `targets:create` dan `devices:create`; target/device memakai `read|write`, device tambahan `credentials:write`. Write mengimplikasikan read, credentials write memerlukan device read, viewer hanya read; admin memiliki seluruh izin organisasi. Tidak ada wildcard lintas tenant atau session grant terpisah.

Acceptance admin membuat membership `pending_mfa` jika enrollment belum selesai; login mengenali pending role sebagai MFA-required dan hanya memberi restricted enrollment. Confirmation mengaktifkan membership atomik. Admin invite baru tidak aktif hingga acceptance dan MFA enrollment selesai. Matching account existing harus login (termasuk MFA jika enabled) sebelum acceptance; mismatch -> 403. Admin tidak dapat mengundang platform admin; platform role hanya dikelola CLI server. Last-admin check mengunci org dan menghitung admin aktif/enrolled, bukan pending invitation. Bootstrap org tanpa admin aktif hanya dapat diperbaiki platform melalui resend/reissue invite awal; endpoint POST `/platform/organizations/{id}/admin-invitations` (recent MFA, `{email}` -> 201) hanya sah bila belum ada admin aktif, tidak menimpa organisasi yang sudah onboarding.

## 4. Device, integrasi dan audit

Tambahan pada tracking resource Device: `enabled:boolean` default true. `PATCH /devices/{id}` boleh mengubah `enabled` hanya dengan device write. Menjadi false mencabut seluruh device credential aktif secara atomik; true tidak mengaktifkan token lama. `credentials/rotate` memerlukan device aktif, `devices:credentials:write`, dan recent auth untuk portal; application integration token dilarang memanggilnya.

`GET /devices/{id}/credentials` memerlukan credentials write, menghasilkan metadata `{id,created_at,revoked_at,active}` tanpa token/hash. `DELETE /devices/{id}/credentials/{credential_id}` memerlukan recent auth + credentials write, 204; mencabut token tanpa menghapus histori.

`POST /organization/application-tokens`: org admin + recent MFA, body `{name,scopes,device_ids,target_ids}`, 201 `{id,token,expires_at}` sekali. Scopes hanya tracking read/write/subscribe, mengecualikan credentials dan management; resource IDs wajib eksplisit. `GET /organization/application-tokens` metadata only, `DELETE /organization/application-tokens/{id}` 204 revoke. Token terikat penerbit/tenant, TTL 90 hari; semua akses adalah intersection scope token, resource list dan hak owner saat request. Pemakaian session memerlukan `sessions:read|write` dan permission owner saat ini pada target serta device di allowlist; scope sesi terpisah dari scope CRUD target/device.

`GET /organization/audit-events`: org admin, filter `from,to,actor_id,action,resource_id`, range max 31 hari, pagination sama konvensi. Event `{id,tenant_id,actor_id,action,resource_type,resource_id,outcome,request_id,occurred_at}`; tidak ada secret/raw location. Akses histori mencatat rentang permintaan dan jumlah hasil, bukan koordinat. Platform audit terpisah, tersedia melalui CLI operator; tidak membaca audit lokasi tenant lewat privilege platform.

## 5. WebSocket dan acceptance

Browser mint ticket dengan cookie+CSRF+tenant header, lalu gunakan single-use ticket untuk handshake seperti kontrak tracking. Ticket mengikat session ID, tenant dan authz version; expiry 60 detik. Device token tidak dapat mint ticket. Origin selalu diperiksa. Non-browser application token dapat memakai Authorization header handshake dan tenant token sendiri. Refresh browser tidak memperpanjang absolute expiry.

Tes wajib: CSRF, replay TOTP/recovery/token links, expired challenges, password reset tetap mewajibkan MFA, last-admin concurrent mutation, cross-tenant grant/invite, tab tenant berbeda, suspend organization/device bersamaan dengan ingestion, revocation REST/WS dan secret tidak muncul di response list/log/cache. Rate limits dan timeout mengikuti Operations. JSON schema/OpenAPI untuk semua route ini dibuat pada milestone kontrak sebelum coding modul terkait.
