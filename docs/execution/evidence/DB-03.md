# DB-03 — RLS dan repositories tenant-scoped

Tanggal: 2026-10-19  
Status: selesai

## Implementasi

- Menambahkan migration `202610190004_tenant_rls.sql`. Seluruh 14 tabel yang saat ini memiliki tenant boundary memakai `ENABLE ROW LEVEL SECURITY` dan `FORCE ROW LEVEL SECURITY`, dengan policy tenant berbasis `current_setting('app.tenant_id', true)` yang null-safe. Owner tabel bukan role login dan bukan `BYPASSRLS`.
- Membuat capability roles `gps_tracking_app`, `gps_tracking_auth`, `gps_tracking_schema_owner`, `gps_tracking_device_lookup_owner`, `gps_tracking_retention_worker`, dan `gps_tracking_platform_provisioner`. Semua `NOLOGIN`; hanya owner fungsi device lookup dan platform-provisioner memiliki `BYPASSRLS`, keduanya tanpa keanggotaan dari app role. Auth capability dapat membaca/mengelola tabel login global yang diperlukan dan membaca membership hanya di tenant context; tidak mempunyai grants tracking. Role app menerima grants terbatas; audit append-only untuk app; token hash tidak bisa dibaca langsung.
- Menambahkan `lookup_device_credential(BYTEA)`, sebuah `SECURITY DEFINER` dengan fixed `search_path`, `row_security=off`, dan owner BYPASSRLS yang hanya dapat membaca kolom minimum dari tiga tabel. `PUBLIC` tidak dapat menjalankan fungsi. Hasil dibatasi ke tenant/device/policy untuk credential aktif milik device enabled dalam organisasi active; fungsi tidak membaca atau mengembalikan lokasi.
- Retention worker hanya dapat memilih dan menghapus posisi/idempotency yang sudah expired dan audit lebih dari 365 hari. Ia tidak dapat menghapus target atau membaca posisi yang belum expired.
- Platform-provisioner dapat mengelola hanya baris organization/invitation/outbox yang diperlukan dan menulis audit; tidak diberi privilege tabel lokasi. Mapping principal login dilakukan di bootstrap/secret provisioning, bukan dengan password dalam migration.
- Menambahkan `begin_tenant_transaction` dan `set_tenant_context`, yang memakai `set_config(..., true)` sehingga tenant hanya terset dalam transaksi. Menambahkan storage lookup API untuk digest credential.
- Dokumentasi server menjelaskan pemetaan DB role dan kewajiban penggunaan transaksi ber-context. Membership/grant object authorization tetap tanggung jawab service layer.

Tabel user/authentication yang tidak memiliki tenant ID tetap global sesuai desain login lintas organisasi; app capability tenant tidak diberi grants atas tabel tersebut. Tabel `object_grants` belum ada pada schema sampai task provisioning/authorization berikutnya; object-level authorization tidak diklaim selesai oleh RLS ini.

## Batas

- Runtime login principals belum dibuat karena password/credential runtime diatur deployment/bootstrap. Operator perlu membuat login terpisah dan memberi keanggotaan capability role yang sesuai; jangan beri app membership pada schema-owner, lookup-owner, retention-worker, atau platform-provisioner.
- Role app belum dihubungkan ke server pool maupun endpoint; API/service authZ, membership, object grants dan tenant transaction call sites dikerjakan task backend selanjutnya.
- Platform provisioning tetap harus memeriksa principal/otorisasi management pada service layer. `BYPASSRLS` role ini sengaja tidak memiliki privilege baca/tulis posisi.
- Hosted CI dan deployment tidak dijalankan.
