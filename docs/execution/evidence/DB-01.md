# DB-01 — Migrasi identity, tenant dan auth

Tanggal: 19 Oktober 2026. Status: `done`.

## Implementasi

- Menambahkan SQLx 0.8.6 dengan PostgreSQL, Tokio/Rustls dan embedded migrations; `tracking-storage::MIGRATOR` menyediakan migration runner yang dipanggil sebagai langkah migrasi satu kali, bukan oleh setiap API process saat startup.
- Migrasi `202610190001_identity.sql` membuat `organizations` dan `users`, email canonical lowercase/trim unique, status/role metadata, serta check constraints.
- Migrasi `202610190002_membership_auth.sql` membuat `memberships`, `invitations`, `auth_sessions`, `auth_challenges`, `mfa_factors`, `recovery_codes`, `account_tokens`, dan `email_outbox`. Constraint mencakup tenant/user uniqueness, satu undangan pending per tenant/email, token digest 32 byte unique, satu faktor aktif/pending per user, batas attempts, status/time consistency, single active token per user/purpose, outbox ciphertext non-empty dan expiry <=72 jam.
- `consume_account_token` dan `consume_recovery_code` memakai conditional `UPDATE ... RETURNING` di dalam transaksi caller sehingga request bersamaan hanya bisa mengonsumsi record sekali dan update lanjutan dapat berada pada transaksi yang sama.
- Menambahkan tes PostgreSQL ter-ignore secara default dan dipanggil secara eksplisit di CI dengan PostGIS disposable. Tes menerapkan migrasi pertama sebagai baseline lalu meng-upgrade, menjalankan migrator ulang, menguji tenant NOT NULL/FK dan membership uniqueness, serta mengadu dua consumer paralel atas account token dan recovery code.
- CI menambah service PostgreSQL/PostGIS ber-image digest yang sama dengan Compose lokal.
